# CLAUDE.md

Conventions for agents writing in this repository. It is a documentation repository: the rules are about what to record and what to
leave in the code. This file is the core, the rules that hold in every session. The procedures are in `process/`, one file each, and
are read when their trigger fires (the list "When to read what" below).

## First run

If `FIRST-RUN.md` exists in the root, read it before anything else and run the interview it describes: where does the truth of each
kind of fact live, and how is it read with a command? Until `reference/sources-of-truth.md` exists, do not write other pages: every
`verify_with` and every `## Sources` entry rests on it. Tier 0 warns `first-run-pending` while the file exists.

## The one rule

**Write only what cannot be derived from a repository or a live command.**

Before adding anything, ask: could an agent get this by reading a source file or running a command? If yes, link to it and stop.
Copied values rot silently and are worse than an empty page, because they are trusted.

What belongs here: how the pieces fit together, why a design was chosen, procedures that took trial and error to get right,
failure modes and their signatures. What does not: lists of endpoints, configuration keys, values, schemas, counts and statuses that a
command prints.

## Start from INDEX.md

[INDEX.md](INDEX.md) has one line for each page: its path, title, `status`, size in KB, the question it answers and its keywords.
Grep it before you open a page (`grep -i WORD INDEX.md`), then open the page the line names; do not read the index whole and do not
walk the directories. It is generated by `scripts/make-index.sh` from the `summary:` and `keywords:` of the pages: change them in the
page, never in the index, and when a change makes a `summary:` untrue, fix it in the same piece of work and run the script (Tier 0
fails when `INDEX.md` is out of date).

## A page over 40 KB is never read whole

Take the outline first: `scripts/page-outline.sh PAGE` prints the headings with their line numbers and the size of each section.
Then read the section you need with an offset and a limit. A page read whole is paid for again in every later call of the session.

## When to read what

Read the file when its trigger fires, before the work it describes.

- **Writing or reading the front matter of a page** (the keys, what `verified`, `unverified` and `stale` mean, the forms of a `Sources` entry, what `n/a` means): [process/frontmatter.md](process/frontmatter.md).
- **Verifying pages, planning the budget of a session, closing a session, or the age warning of Tier 0**: [process/verification.md](process/verification.md).
- **Finishing a change, or finding a statement that is no longer true**: [process/keep-documentation-current.md](process/keep-documentation-current.md).
- **Opening, updating or merging a pull request**: [process/pull-requests.md](process/pull-requests.md).
- **A decision with real trade-offs that someone will need to reconstruct**: [process/adr.md](process/adr.md).

## Never write a secret value

**This is a hard rule.** No password, token, key, certificate body, or connection string with credentials goes into this repository,
in any file, ever. Not in an example, not in a fenced block, not "temporarily", not with a comment saying it is a test value.

It is enforced three times over: `.githooks/pre-commit` runs `scripts/secret_sweep.py` on the staged changes (switch it on once per
clone with `git config core.hooksPath .githooks`); `.github/workflows/secret-sweep.yml` runs the same sweep on the whole tree and on
every commit ever made; and Tier 0 runs it again. A finding is a secret until a person has shown it is not. If a secret has been
committed, **rotate it first** and only then remove it: removal from git does not undo a disclosure.

Write the *location* instead: which file, which store, which entry, and what kind of credential it is. Personal data and customer
data follow the same rule; group D1 of the first run records what else must never be written.

## Never write an identifier you did not read

A name, an address, an id, a version, a count or a status goes into a page only if you read it from its source in this session, and
the source is in `## Sources`. If you remember it or were told it, write it as `team knowledge`, `unverified`. A plausible value in a
placeholder slot is copied into a command by the next reader: use a capitalised placeholder (`NAME`, `ENVIRONMENT`) instead.

## Stating facts versus guessing

`status` is a claim about evidence, not about confidence. `verified` means you ran the commands and saw the output; anything else is
`unverified`. Say in the report of a session which pages you checked and which you only read. Downgrading a page you could not check
is the useful action, not a failure. A statement you could not check is written as unchecked, in the page.

## Records are formulations, not conversations

This section applies while `record_style = strict` in `handbook.cfg` (the first run decides it). Pages are in English with plain
punctuation: no em dash, no quotation of a person, no "X said". Write the fact and its source. A decision names the date and the role
that made it, and a claim a person made is a `team knowledge` entry, not a quotation. Tier 0 blocks text in another alphabet
(`non-english-text`), warns on a phrase that introduces a quotation (`quoted-message`), and warns on an em dash.

## Copy conventions, never content

A handbook may copy the conventions of another one. It never copies its content: a project name, a host, a repository or an
organisation taken from a neighbour is wrong here by definition. `scripts/foreign-identifiers.txt` lists what must not appear;
Tier 0 blocks a hit (`foreign-identifier`).

## Tier 0 runs before every commit

Run `scripts/tier0.sh` before every commit (the pre-commit hook does it). It has no network and no authentication, and takes seconds.
`blocking` fails the commit; `warning` and `info` are prompts to look. When a check fires on your prose, reword the prose; never loosen
a pattern, and never document an "expected" hit. Run `python3 scripts/test_tier0.py` (and the other `scripts/test_*.py`) when you
change a script.

## Diagrams

A diagram is a closed mermaid block that starts with a diagram type and carries a caption "As of DATE" under it. A diagram without a
date is a picture of an unknown past. Tier 0 checks it.

## Settings

`handbook.cfg` holds four settings: `record_style`, `verified_max_age_days`, `index_folders` (the folders whose pages `INDEX.md` lists)
and `record_folders` (the folders of dated records that do not age). Tier 0 reports an unknown key or a value that is not allowed as
blocking.

## Keep the documentation current

A change is finished when every page that states the old fact says the new one, and a statement found to be untrue is fixed in the
session that finds it. The procedure is [process/keep-documentation-current.md](process/keep-documentation-current.md).
